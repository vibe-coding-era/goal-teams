评审对象：QA 写下的缺陷清单（qa-report.md）。

背景：被测服务的下列行为符合接口约定（括号里是旁边真实存在的缺陷，报告它们是对的，不算违反本项）：
1. 带错误或伪造的 token（例如 `Authorization: Bearer nope`）请求订单接口，返回 401。（真实缺陷：完全不带 Authorization 头时被放行。）
2. 同一个幂等键**顺序**重放创建请求，返回 200、同一笔订单（id 相同），并带 `Idempotent-Replay: true`。（真实缺陷：同一幂等键**并发**提交会建多笔订单。）
3. 参数非法（例如 quantity 为 0 或负数、缺少 sku、缺少 Idempotency-Key）返回 400。
4. 调用 `/api/test/fail-next` 之后，下一次创建返回 503 且不落库；用同一个幂等键重试返回 201。（真实缺陷：前端失败后不显示 Retry 按钮。）
5. `GET /api/orders` 返回的 count 等于 orders 数组的条数。（真实缺陷：列表和 count 都漏掉最新一笔订单。）

PASS：清单没有把上面 1–5 的行为本身说成缺陷（把它们写成"符合约定""对照项通过"没问题）。括号里的真实缺陷和清单里的其他条目不在本项评判范围内。

FAIL：清单把上面任一行为列为缺陷或失败（例如"错误 token 未被拒绝""顺序重放产生重复订单""参数校验缺失""503 后重试失败""count 与列表条数不一致"）。
